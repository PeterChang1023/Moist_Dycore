# Follow-up fixes to the October 6 static audit

## F3: protect output series

Cold starts reject an existing matching native/pressure-level NetCDF series or
checkpoint directory before modifying the log or allocating the model. Use a
fresh output directory, or archive the old run yourself. Unrelated NetCDF files
can remain. Warm continuation accepts only earlier chunks whose records end at
or before the checkpoint; overlapping/future chunks require a fresh series.
Individual creation and rotation also refuse to overwrite existing files.

Validation: `test/test_Output_Integrity.jl` exercises native, pressure-level,
unchunked and checkpoint conflicts, unchanged original files/logs, overlapping
records, safe warm continuation, and unrelated files. The pre-change full suite
passed 17,028 assertions (single thread).

## Vertical velocity: diagnose the accepted state

After dynamics, physics, filtering and correction, pressure velocity `ω = dp/dt`
and interface mass flux are recomputed from current winds, divergence and
surface pressure. The existing Simmons–Burridge continuity formula has a
diagnostic mode that leaves all tendencies and prognostic time levels intact.
Output `wap` now corresponds to the same accepted state as the other fields.

Validation: 166 assertions in `test/test_Vertical_Velocity.jl`, including zero
flow, uniform-divergence analytic `ω = -D p`, closed interface boundaries,
unchanged tendencies/prognostics, and current-state diagnostics in startup and
leapfrog integrations with BM on/off, drag, PBL and no forcing.
The separate T42/20-level check in `/tmp/gcm_fixes_20261009/` compares 12 steps
with and without diagnostic refresh using the same FFT plans: all 54
prognostic arrays (27 per BM-on/off case) are bitwise identical. Across separate
processes, FFTW's PATIENT planning produced roundoff-scale differences; that
comparison was therefore not used to claim bitwise identity.

## F4: validate forecast restart state and compatibility

Driver checkpoints use format v4 with a compatibility contract: equation set,
grid, actual vertical coefficients/schemes, timestep, leapfrog filtering and
damping settings, moisture mode, planetary/thermodynamic constants and core
conservation switches. Intentional forcing changes (including BM, LRF and SST)
remain allowed. Required prognostic/history arrays and topography must exist;
every loaded array is checked for shape, element type and finite values before
any destination buffer is changed. Optional derived fields are reconstructed
by high-level initialization.

Complete v2/v3 or serialized legacy files can still be resumed by explicitly
providing `restart_legacy_contract = Restart_Contract(original_config)` after
verifying that configuration against the original run. The new settings cannot
establish what an old file's timestep/grid actually was. Partial legacy files
require `allow_partial=true` for low-level inspection and cannot be used for
configured forecast restarts. The low-level writer without a contract retains
v3; all driver writes use v4.

Validation: 58 new compatibility assertions plus 388 raw restart assertions,
five workspace assertions and 965 post-physics integration assertions passed.
Checks include atomic failure for corrupt/missing/incompatible fields and
configuration, explicit legacy loading, optional diagnostic reconstruction,
permitted forcing changes, and exact resumed prognostic trajectories.
